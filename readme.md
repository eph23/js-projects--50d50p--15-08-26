## 📜 Rules

- ✅ Minimum one project per day, in order — no cherry-picking the easy ones. If you've got time/energy, knock out more — the tracker below is by **project number**, not locked to a single date each.
- ✅ Code first, THEN look things up — resist the urge to copy-paste from the course before attempting.
- ✅ Log at least one new concept, method, or gotcha per project (see table below).
- ✅ Watch for the **credit card effect** — don't overthink simple DOM tasks under pressure.
- ✅ If a day is missed, don't renumber — just mark it and keep going. Consistency > streak perfection.
- ✅ Separate Git repo per the existing convention (chapter exercises get their own repo — same idea here).
- ✅ Quality still counts even when moving fast — don't blitz through 3-4 in a day just to pad the count. If you double up, make sure each one still gets a proper concept note.

## 🎯 The Course's Goal

Move from *knowing JS syntax* to *building with it on instinct*. Each project is small and scoped on purpose — no frameworks, no build tools, just the DOM and vanilla JS — so the reps build real muscle memory for manipulating the browser directly. By project 50, things like event handling, array/object methods in UI contexts, timers, and fetch/async shouldn't need conscious thought anymore. That fluency is exactly what makes React (and everything after it) click faster instead of feeling like starting over.
